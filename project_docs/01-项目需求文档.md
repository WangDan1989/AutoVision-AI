# 项目需求文档

## 1. 文档信息

- 项目名称：小说驱动的 AI 成片生产系统
- 文档类型：项目需求文档
- 版本：v1.0
- 编写依据：当前对话中已确认的项目方向与 V1 范围

## 2. 项目背景

当前市场上多数 AI 内容工具只能处理单点任务，例如文案生成、配音生成、图片生成或视频生成，但无法从长文本叙事直接进入成片生产流程。项目目标不是简单串联多个 AI 工具，而是建设一套从小说内容输入到短片 Demo 输出的完整生产系统。

该系统面向的不是通用办公用户，而是具备内容创作需求、希望借助 AI 和游戏引擎快速完成短片生产的创作者或小型团队。V1 的目标不是追求电影级写实效果，而是先稳定跑通一条可重复的、可演示的、可扩展的小说驱动成片链路。

## 3. 项目目标

### 3.1 总体目标

建设一套以小说内容为输入，以 Godot 为导演与拍摄引擎，以 Blender 为 3D 资产修复与标准化工具，以 Python 为流程编排后端的 AI 成片生产系统，实现从文本到短片 Demo 的自动化流程。

### 3.2 V1 目标

- 输入一部小说、一个章节或一个剧情片段
- 自动完成剧情拆解，输出场次、镜头、角色、场景、道具需求
- 生成少量核心角色与基础场景、道具资产任务
- 通过 Blender 对资产进行修复、标准化和格式统一
- 在 Godot 中自动摆场、摆角色、调镜头并输出基础演出
- 通过单一主方案的 TTS 生成旁白和角色语音
- 通过 FFmpeg 完成音视频合成，输出可观看短片 Demo

### 3.3 V1 不做的事情

- 电影级微表情与高复杂面部捕捉
- 完全真人级数字人替身
- 多套 TTS 并行接入与动态切换
- 复杂多角色群戏协同系统
- 全自动长篇小说整本高质量出片

## 4. 产品定位

### 4.1 产品定义

本项目是一个小说驱动的 AI 成片生产系统，重点是生产链路和稳定出片能力，而不是单一模型能力展示。

### 4.2 核心定位

- 定位：AI 驱动的短片生产系统
- 表现形态：以本地运行环境为主的桌面化生产工具链
- 关键能力：剧情理解、任务拆解、资产标准化、自动导演、自动配音、自动合成导出

### 4.3 核心价值

- 将小说内容转化为可执行的镜头生产任务
- 降低从文本到短片 Demo 的人力成本
- 形成可重复执行的数字人短片生产流水线
- 为后续升级长篇、角色库、镜头模板库和更高质量资产生成打基础

## 5. 用户与使用场景

### 5.1 目标用户

- 个人内容创作者
- AI 短片制作团队
- 视觉小说、网文、短剧方向的实验型团队
- 需要做故事型内容验证的研发团队

### 5.2 典型场景

- 将小说章节快速转成可演示的剧情短片
- 将文字设定转换为角色、场景、道具和镜头脚本
- 快速验证一套数字演员是否能支撑连续剧情演出
- 验证从剧情拆解到最终导出的完整工作流

## 6. 核心业务流程

### 6.1 业务主链路

1. 导入小说内容
2. 对小说文本进行结构化拆解
3. 识别角色、场景、道具、动作和对白
4. 生成场次与镜头脚本
5. 生成或准备角色、场景和道具资产
6. 使用 Blender 进行资产修复、标准化和导出
7. 将镜头脚本和资产导入 Godot
8. 在 Godot 中自动摆场、角色放置、镜头调度和演出
9. 调用 TTS 生成音频
10. 合成视频、字幕和音频
11. 输出短片 Demo

### 6.2 数据流转核心对象

- 小说原文
- 场次结构
- 镜头脚本
- 角色设定
- 场景设定
- 道具设定
- 资产任务
- 标准化 3D 资产
- 演出计划
- 语音结果
- 最终导出结果

## 7. 功能需求

### 7.1 小说导入模块

#### 7.1.1 功能说明

负责导入小说全文、章节、片段或人工粘贴文本，并完成基础清洗和切分。

#### 7.1.2 需求点

- 支持文本文件导入
- 支持章节级导入与片段级导入
- 支持手动编辑导入内容
- 支持文本基础清洗，例如空行、乱码、特殊符号处理
- 支持对导入内容进行版本保存

### 7.2 剧情拆解模块

#### 7.2.1 功能说明

通过 LLM 对小说内容进行结构化理解，生成场次、镜头、角色、场景、道具和对白等生产数据。

#### 7.2.2 需求点

- 提取场次列表
- 提取主要角色与次要角色
- 提取核心场景
- 提取关键道具
- 提取对白、动作和叙事重点
- 输出可被下游系统使用的结构化结果

### 7.3 镜头脚本模块

#### 7.3.1 功能说明

将剧情拆解结果进一步转化为可拍摄的镜头脚本。

#### 7.3.2 需求点

- 场次拆镜
- 镜头类型定义
- 机位说明
- 时长建议
- 角色动作描述
- 台词和旁白映射
- 场景与道具引用关系

### 7.4 资产任务模块

#### 7.4.1 功能说明

根据镜头脚本生成角色、场景、道具和动画需求任务。

#### 7.4.2 需求点

- 为角色生成资产任务
- 为场景生成资产任务
- 为道具生成资产任务
- 标注资产优先级
- 标注镜头依赖关系
- 输出资产清单和任务队列

### 7.5 3D 资产修复与标准化模块

#### 7.5.1 功能说明

使用 Blender 对资产进行整理、修复和标准化，统一为 Godot 可消费的格式。

#### 7.5.2 需求点

- 资产格式校验
- 基础骨骼和挂点修复
- 命名标准化
- 材质和贴图检查
- 导出为 glTF 或 GLB
- 输出资产状态和错误报告

### 7.6 Godot 导演拍摄模块

#### 7.6.1 功能说明

在 Godot 中根据镜头脚本和资产结果自动完成摆场、摆人、镜头切换和基础演出。

#### 7.6.2 需求点

- 读取镜头脚本
- 读取角色、场景、道具资产
- 自动实例化场景
- 自动摆放角色和道具
- 自动设置摄像机位置、角度和切换
- 生成基础镜头动画
- 输出镜头预览或镜头序列

### 7.7 TTS 配音模块

#### 7.7.1 功能说明

负责角色对白、旁白和基础语音合成。

#### 7.7.2 需求点

- 单一主方案 TTS 接入
- 角色语音配置
- 台词转音频
- 旁白转音频
- 输出音频文件与时长信息

### 7.8 合成导出模块

#### 7.8.1 功能说明

负责将 Godot 导出的画面序列、音频、字幕、背景音进行合成并输出视频。

#### 7.8.2 需求点

- 音频拼接
- 视频拼接
- 字幕叠加
- 输出分辨率配置
- 输出码率配置
- 最终视频导出
- 导出记录保存

## 8. 非功能需求

### 8.1 稳定性

- V1 的首要目标是稳定出片
- 同一输入在相同配置下应尽量得到可复现结果
- 系统应具备异常日志和失败步骤定位能力

### 8.2 可维护性

- 模块边界清晰
- 数据格式统一
- 关键流程可回放
- 关键任务有状态记录

### 8.3 可扩展性

- 后续可替换或新增模型
- 后续可增加资产模板和镜头模板
- 后续可接更高质量数字人或更复杂导演逻辑

### 8.4 性能与运行要求

- 云端 Demo 不作为第一目标交付形态
- 由于存在 Strata LLM 相关内容与本地依赖，完整演示链路应支持本地环境运行
- 第一阶段优先保障本地闭环可运行，而不是远程沙箱可运行

## 9. 关键约束

- 必须围绕本地运行环境设计
- 必须优先保障从小说到短片 Demo 的闭环打通
- 必须使用 Godot 作为导演与拍摄核心引擎
- 必须使用 Blender 作为资产修复与标准化工具
- 必须优先做高写实、偏真人、可控的数字演员路线

## 10. 风险与应对

### 10.1 风险项

- LLM 拆解质量不稳定，影响下游全链路
- 3D 资产质量不统一，导致 Godot 自动导演失败
- 角色一致性不足，影响可观看性
- TTS 情绪与节奏不稳定，影响演出效果
- 本地环境依赖复杂，影响搭建效率

### 10.2 应对建议

- 统一 JSON Schema 与结果校验
- 建立角色、场景、道具标准化规范
- 设计可回退和人工修正节点
- 第一版先减少角色数量和场景复杂度
- 优先保证稳定链路，不追求全自动极限

## 11. V1 验收标准

- 能成功导入小说片段或章节
- 能输出结构化剧情拆解结果
- 能输出镜头脚本
- 能生成少量核心角色和基础场景资产任务
- 能通过 Blender 完成资产标准化输出
- 能在 Godot 中自动完成基础拍摄
- 能完成 TTS 配音
- 能完成最终导出
- 能产出一个可观看的短片 Demo

## 12. 结论

本项目已经从概念阶段进入可规划落地阶段。V1 应以稳定出片和完整生产链路打通为核心目标，以小说输入、剧情拆解、资产标准化、Godot 自动导演、TTS 配音和 FFmpeg 导出为主线推进，优先在本地环境完成可运行 Demo。
