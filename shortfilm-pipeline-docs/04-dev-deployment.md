# 开发部署文档

## 1. 适用范围

本文用于本地开发、联调、部署与排障，覆盖以下组件：

- Godot 4
- Strata 或 Ollama
- Piper TTS
- Rhubarb Lip Sync
- 本项目工程文件、缓存、日志、导出目录

本文不包含云端部署方案，默认所有组件运行在本机或本地局域网内可信环境。

## 2. 依赖清单

### 2.1 必选依赖

| 组件 | 版本建议 | 作用 |
| --- | --- | --- |
| Godot | 4.x | 编辑器、运行时、渲染与录制 |
| Strata 或 Ollama | 当前稳定版 | 本地 LLM 服务 |
| Piper TTS | 当前稳定版 | 本地语音合成 |
| Rhubarb Lip Sync | 当前稳定版 | 音频转嘴型关键帧 |

### 2.2 输入资源约束

| 类别 | 要求 |
| --- | --- |
| 角色/场景/道具 | GLB/GLTF，许可证仅限 CC0/MIT/Apache-2.0 |
| 动作片段 | 与角色骨骼兼容，具备可复用命名规范 |
| 音效/BGM/环境音 | 本地可离线访问的音频文件 |
| 人设/脚本/机位 | JSON 文件，符合本设计包 Schema |

## 4. 端口规划

本项目不强依赖固定端口，但为联调与排障统一，建议采用以下规划：

| 组件 | 建议端口 | 说明 |
| --- | --- | --- |
| Strata | `11435` | 仅建议值，可按实际调整 |
| Ollama | `11434` | 常见本地默认端口 |
| Godot 编辑器/运行时 | 无固定业务端口 | 主体为本地进程 |
| Piper TTS | 无固定端口 | 建议以 CLI 方式调用 |
| Rhubarb Lip Sync | 无固定端口 | 建议以 CLI 方式调用 |

设计要求：

- 工程配置中必须显式保存后端主机与端口。
- 不允许把端口写死在脚本逻辑里。

## 5. 启动顺序

建议启动顺序如下：

1. 准备模型文件、Piper 声库、Rhubarb 可执行文件。
2. 启动 LLM 后端服务。
3. 执行 LLM 健康检查。
4. 验证 Piper 与 Rhubarb 可执行文件是否可调用。
5. 启动 Godot 工程。
6. 加载项目配置，执行引用检查。
7. 进入调试模式或拍摄模式。

原因：

- LLM、TTS、Lip Sync 组件先就绪，便于工程加载时直接完成运行前校验。
- 若后端不可用，可在进入拍摄前就切换为保底模式。

## 6. 开发环境建议

### 6.1 Windows

- 适合作为 Godot 编辑与资产整理主环境。
- 需确认 Piper、Rhubarb、Strata/Ollama 的可执行路径已加入环境变量，或在工程配置中显式配置绝对路径。

### 6.2 Linux

- 适合作为本地推理与离线批处理主环境。
- 建议为模型目录、缓存目录、导出目录预留足够磁盘空间。

## 7. LLM 模型与 128B 硬件评估

### 7.1 基本判断

128B 级开源模型可以接入，但对普通单卡桌面环境压力极高。若目标是“实时对白生成”，128B 只适合高端多卡或超大内存环境；若目标是“离线预生成台词”，则可接受更低吞吐。

### 7.2 建议分档

| 模型规模 | 典型用途 | 建议硬件 |
| --- | --- | --- |
| 7B-14B | 实时对白、快速迭代 | 8-24 GB VRAM |
| 32B | 较高质量对白 | 24-48 GB VRAM |
| 70B | 高质量对白、离线优先 | 48-80 GB VRAM |
| 128B | 重质量、离线预生成更现实 | 96 GB 以上 VRAM 或 128 GB 以上内存配合量化与部分 GPU offload |

### 7.3 128B 部署建议

- 若使用 128B，优先考虑“先批量生成台词与音频，再进入引擎渲染”的工作流。
- 若显存不足，不建议强行在镜头录制时实时调用 128B 模型。
- Strata/Ollama 的实际可运行上限取决于量化方式、上下文长度、KV Cache 与并发数，需以目标机器实测为准。

### 7.4 显存与内存评估原则

- 参数量越大，模型权重、KV Cache、运行时开销越高。
- 上下文越长、并发越高，额外内存消耗越大。
- 128B 场景下应降低并发，避免多个对白同时请求后端。
- 若实际部署机无法稳定承载 128B，应通过工程配置切换更小模型，或直接启用保底模式。

## 8. 组件集成建议

### 8.1 Strata / Ollama

- 通过统一后端配置项接入。
- 启动后先调用健康检查接口，再允许进入拍摄链路。
- 运行中只暴露标准结果给业务层，不传递底层专有字段。

### 8.2 Piper TTS

- 优先使用本地 CLI 生成 wav。
- 输出目录建议落在 `audio/dialogue-cache/`。
- 同文案与同 voice 配置生成相同缓存键，避免重复推理。

### 8.3 Rhubarb Lip Sync

- 输入使用 TTS 输出 wav。
- 输出建议落在 `cache/lipsync/`。
- 仅在对白语音可用时触发，失败后不阻塞角色动作与镜头切换。

## 9. 启动前检查清单

- Godot 版本符合 4.x
- 资产许可证符合 CC0/MIT/Apache-2.0
- Strata 或 Ollama 至少一个后端可达
- Piper 声库文件可用
- Rhubarb 可执行文件可运行
- 工程配置通过 JSON Schema 校验
- 脚本引用的角色、机位、动作、音频文件均存在
- 缓存目录、日志目录、导出目录具备写权限

## 10. 故障排查

### 10.1 LLM 后端不可达

表现：

- 健康检查失败
- 对话请求超时
- 熔断器频繁打开

排查步骤：

1. 确认主机、端口、模型标识与工程配置一致。
2. 确认后端服务已加载目标模型。
3. 检查是否显存或内存不足导致后端进程异常退出。
4. 降低并发与上下文长度，观察是否恢复。
5. 切换保底模式，验证主流程是否可继续。

### 10.2 TTS 失败

表现：

- 无 wav 输出
- 音频生成耗时异常长

排查步骤：

1. 检查 Piper 可执行路径与声库路径。
2. 检查输出目录写权限。
3. 检查台词文本是否包含当前声库无法处理的内容。
4. 查看是否已命中缓存，若缓存命中但文件丢失则重建缓存。

### 10.3 Lip Sync 失败

表现：

- 语音存在，但口型不动

排查步骤：

1. 检查 wav 是否存在且可正常播放。
2. 检查 Rhubarb 输出文件是否生成。
3. 检查角色面部驱动映射是否匹配当前模型。
4. 临时关闭口型驱动，确认剧情与音频是否可继续推进。

### 10.4 导出失败

表现：

- 视频编码中断
- 序列帧不完整

排查步骤：

1. 检查导出路径磁盘空间。
2. 检查编码参数是否受当前环境支持。
3. 先尝试导出 PNG 序列帧，定位是渲染问题还是编码问题。
4. 核对日志中的 `trace_id` 与导出任务 ID。

### 10.5 工程读写异常

表现：

- 打开工程失败
- 保存后重新加载丢失配置

排查步骤：

1. 使用 Schema 校验工程文件。
2. 检查文件引用路径是否失效。
3. 确认缓存目录未被误当作主配置目录。
4. 检查版本号是否与当前工程模板兼容。

## 11. 性能建议

- 大模型优先离线预生成，实时模式优先选择较小模型。
- 语音缓存与唇形缓存默认开启。
- 对长剧集建议按集拆分工程，减小单工程索引规模。
- 导出时避免同时触发高并发 LLM 推理任务。
