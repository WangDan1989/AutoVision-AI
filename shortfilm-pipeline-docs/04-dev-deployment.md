# 开发部署文档

## 1. 适用范围

本文用于新的 AI 建模版项目，覆盖以下组件：

- Godot 4
- 开源 AI 3D 资产生成后端
- Strata 或 Ollama
- Piper TTS
- Rhubarb Lip Sync
- 工程、草稿资产、批准资产、质量报告、缓存、日志与导出目录

默认前提是所有组件运行在本机或本地局域网可信环境中，不依赖闭源云服务。

## 2. 依赖清单

### 2.1 必选依赖

| 组件 | 版本建议 | 作用 |
| --- | --- | --- |
| Godot | 4.x | 编辑器、运行时、渲染与录制 |
| 开源 AI 3D 生成后端 | 当前稳定版 | 角色/场景/道具生成 |
| Strata 或 Ollama | 当前稳定版 | 本地 LLM 服务 |
| Piper TTS | 当前稳定版 | 本地语音合成 |
| Rhubarb Lip Sync | 当前稳定版 | 音频转嘴型关键帧 |

### 2.2 输入资源

| 类别 | 要求 |
| --- | --- |
| 人设 | JSON，包含对白约束和外观提示 |
| 脚本 | JSON，符合脚本 Schema |
| 机位 | JSON，符合机位 Schema |
| 参考图 | 本地图片，可选，用于 image-to-3D 或混合生成 |
| 动作片段 | 与目标骨架兼容，可复用命名规范 |
| 音效/BGM/环境音 | 本地离线可访问音频 |

## 4. 端口规划

建议规划如下：

| 组件 | 建议端口 | 说明 |
| --- | --- | --- |
| AI 3D 生成后端 | `11500` | 建议值，可配置 |
| Strata | `11435` | 建议值 |
| Ollama | `11434` | 常见本地默认端口 |
| Godot | 无固定业务端口 | 本地进程 |
| Piper TTS | 无固定端口 | 优先 CLI |
| Rhubarb Lip Sync | 无固定端口 | 优先 CLI |

要求：

- 所有端口都必须写入工程配置，不允许写死在脚本里。
- AI 3D 生成后端和 LLM 后端分开配置，便于单独排障。

## 5. 启动顺序

建议启动顺序：

1. 准备 AI 建模模型文件、LLM 模型、Piper 声库、Rhubarb 可执行文件。
2. 启动 AI 3D 生成后端。
3. 启动 LLM 后端。
4. 检查 AI 建模后端与 LLM 后端健康状态。
5. 验证 Piper 与 Rhubarb 可执行文件。
6. 启动 Godot 工程。
7. 加载项目配置，执行 Schema 校验、资产锁定校验和引用检查。
8. 进入资产生成、审核或拍摄模式。

原因：

- 资产生成链路和对白链路都需要先就绪，便于工程在启动时完成完整体检。
- 若 AI 建模后端不可用，仍可继续使用已批准资产拍摄。

## 6. 运行模式

### 6.1 资产生产模式

- 用于生成新角色、场景、道具。
- 重点消耗 GPU/内存与磁盘空间。
- 运行结果进入草稿资产目录，需经过后处理和审核。

### 6.2 拍摄模式

- 仅使用批准并锁定的资产版本。
- 不依赖资产生成任务完成。
- 主要依赖 LLM、TTS、Lip Sync 和 Godot 渲染。

## 7. 硬件评估

## 7.1 AI 建模后端

基本判断：

- AI 3D 资产生成的显存和计算需求通常高于单纯 LLM 文本生成中的普通场景。
- 角色生成、场景生成、材质生成、网格细化往往是长任务，不适合作为镜头运行期的同步步骤。
- 更现实的生产方式是“异步生成 -> 后处理 -> 审核定稿 -> 入库复用”。

建议分档：

| 用途 | 建议硬件 |
| --- | --- |
| 小型道具草稿 | 12-24 GB VRAM |
| 角色草稿与基础材质 | 24-48 GB VRAM |
| 高质量角色/中型场景 | 48 GB VRAM 以上 |
| 高频迭代和批量生成 | 多卡或高内存工作站 |

## 7.2 LLM 后端

| 模型规模 | 典型用途 | 建议硬件 |
| --- | --- | --- |
| 7B-14B | 实时对白、快速迭代 | 8-24 GB VRAM |
| 32B | 较高质量对白 | 24-48 GB VRAM |
| 70B | 高质量对白、离线优先 | 48-80 GB VRAM |
| 128B | 重质量、离线预生成更现实 | 96 GB 以上 VRAM 或 128 GB 以上系统内存配合量化 |

## 7.3 128B 使用建议

- 128B 更适合作为对白与剧情离线预生成，不适合作为频繁实时交互默认模型。
- 若同时运行 AI 建模和 128B LLM，建议将两个任务分时段执行，避免显存争抢。
- 若硬件不足，优先保证资产定稿和拍摄稳定性，而不是强行实时跑大模型。

## 8. 资产管线部署建议

### 8.1 目标骨架统一

- 对角色资产建议预定义一个或少量目标骨架配置。
- 所有 AI 生成角色尽量后处理到统一骨架，确保动作库复用。

### 8.2 草稿与批准目录隔离

- 草稿资产只允许进入 `assets/drafts/`
- 通过质检的资产才进入 `assets/approved/`
- Godot 拍摄运行期只读取 `approved`

### 8.3 质量门禁前置

- 在发布资产前完成网格、材质、尺度、骨架和导入检查。
- 质量门禁失败的版本禁止锁定为运行时资产。

## 9. 启动前检查清单

- Godot 版本符合 4.x
- AI 建模后端可达
- Strata 或 Ollama 至少一个后端可达
- Piper 声库文件可用
- Rhubarb 可执行文件可运行
- 工程配置通过 Schema 校验
- 锁定资产版本全部存在且状态为 `approved`
- 脚本、人设、机位、动作、音频引用完整
- 草稿、批准、缓存、日志、导出目录具备读写权限

## 10. 故障排查

### 10.1 AI 建模后端不可达

表现：

- 生成任务提交失败
- 作业长期无进度
- 健康检查失败

排查步骤：

1. 检查主机、端口和模型配置。
2. 检查 GPU/显存是否足够。
3. 检查模型文件是否完整。
4. 检查生成任务是否过大，先缩小资产复杂度重试。
5. 确认失败没有污染已批准资产版本。

### 10.2 资产后处理失败

表现：

- 导出 GLB/GLTF 失败
- 材质缺失
- 骨架不兼容

排查步骤：

1. 检查草稿模型是否存在完整网格和材质资源。
2. 检查尺度和坐标系是否异常。
3. 检查目标骨架配置是否与角色类型匹配。
4. 将失败版本停留在草稿态，不要发布。

### 10.3 质量门禁不通过

表现：

- Godot 导入报错
- 骨骼断裂
- 材质贴图丢失

排查步骤：

1. 查看质量报告的阻断项。
2. 决定是重跑后处理还是回到生成阶段。
3. 若已有旧版本可用，继续使用旧版本拍摄。

### 10.4 LLM 后端不可达

表现：

- 对话请求超时
- 熔断器频繁打开

排查步骤：

1. 核对主机、端口、模型标识。
2. 检查显存或内存不足。
3. 降低上下文长度和并发。
4. 启用预设台词降级验证主流程。

### 10.5 TTS 或 Lip Sync 失败

排查步骤：

1. 检查 Piper、Rhubarb 的可执行路径。
2. 检查输出目录权限。
3. 检查缓存是否已损坏。
4. 在拍摄模式下允许口型关闭或静音占位继续推进。

### 10.6 导出失败

排查步骤：

1. 检查导出磁盘空间。
2. 优先导出 PNG 序列帧排查编码问题。
3. 核对导出日志与任务 ID。

## 11. 性能建议

- AI 建模和 128B LLM 不建议长时间并行运行。
- 对高频对白建议开启音频缓存和口型缓存。
- 对正式生产建议先批量定稿资产，再进入拍摄。
- 对长剧集建议按世界观或章节拆工程，降低资产索引复杂度。

排查步骤：

1. 使用 Schema 校验工程文件。
2. 检查文件引用路径是否失效。
3. 确认缓存目录未被误当作主配置目录。
4. 检查版本号是否与当前工程模板兼容。

## 11. 性能建议

- 大模型优先离线预生成，实时模式优先选择较小模型。
- 语音缓存与唇形缓存默认开启。
- 对长剧集建议按集拆分工程，减小单工程索引规模。
- 导出时避免同时触发高并发 LLM 推理任务。
