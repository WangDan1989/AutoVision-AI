# 集成测试大纲与核心用例

## 1. 目标

验证在“AI 参与 3D 资产生成”的新架构下，各模块仍满足“低耦合、单模块故障不打断已定稿资产拍摄”的核心要求，重点覆盖：

- AI 建模作业提交、后处理、质检与发布
- 资产版本锁定与回滚
- Strata/Ollama 后端切换与对白降级
- TTS、Lip Sync、缓存
- 脚本事件推进、动作优先级、导出
- 工程读写与日志追踪

## 2. 范围

### 2.1 包含

- 工程管理
- AI 资产生成编排
- 资产后处理与质检
- 资产库与版本锁定
- 脚本事件引擎
- 角色状态与动作调度
- Strata/Ollama 双后端适配
- Piper TTS
- Rhubarb Lip Sync
- 音频资源播放
- 自动拍摄与导播录制
- 导出与日志

### 2.2 不包含

- 美术审美好坏的人工主观评价
- 第三方模型内部算法正确性
- 极限压测与长期烧机场景

## 3. 测试环境分层

| 环境 | 用途 |
| --- | --- |
| `env-asset-gen` | AI 建模与资产后处理联调 |
| `env-runtime-min` | 最小拍摄验证，使用已批准资产 |
| `env-runtime-full` | 完整联调，包含 LLM/TTS/Lip Sync |
| `env-export` | 专门验证视频与序列帧导出 |

## 4. 入口与退出标准

### 4.1 入口标准

- 工程文件通过 Schema 校验
- 至少一套角色/场景/道具已批准版本可用于拍摄
- 至少一套 AI 建模后端可用
- Strata/Ollama 至少一套后端可用，或已启用预设台词降级

### 4.2 退出标准

- P0 用例全部通过
- 所有阻断级缺陷关闭
- 生成期与拍摄期故障均有日志和报告可追踪

## 6. 核心用例

### IT-01 AI 建模作业提交与状态追踪

- 目标：验证生成任务可提交、排队、执行并输出草稿资产。
- 前置条件：AI 建模后端可达。
- 步骤：
  1. 提交一个角色生成任务。
  2. 查询任务状态直至完成或失败。
- 预期：
  - 返回标准作业结构。
  - 状态可在 `queued`、`processing`、`draft_ready` 间流转。
  - 失败时保留明确错误码和 `job_id`。

### IT-02 草稿资产后处理与导出

- 目标：验证草稿资产可被后处理成 Godot 可导入格式。
- 前置条件：存在一个 `draft_ready` 草稿资产。
- 步骤：
  1. 执行网格、材质、尺度、导出处理。
  2. 生成运行期资产文件。
- 预期：
  - 输出 `revision_id`
  - 产出 `GLB/GLTF`
  - 文件落在草稿目录，不自动发布

### IT-03 质量门禁阻断未达标资产

- 目标：验证不合格版本不会进入正式资产库。
- 前置条件：存在一个故意注入材质缺失或骨架异常的版本。
- 步骤：
  1. 执行质量检查。
  2. 尝试发布该版本。
- 预期：
  - 质量报告状态为失败
  - 发布请求被拒绝，返回 `E4005`
  - 该版本不可锁定为运行时资产

### IT-04 批准版本锁定与回滚

- 目标：验证运行时始终指向被明确批准的资产版本。
- 前置条件：同一角色至少有两个批准版本。
- 步骤：
  1. 锁定新版本。
  2. 启动拍摄预览。
  3. 回滚到旧版本。
- 预期：
  - 运行时版本切换可追踪
  - 回滚后脚本和拍摄引用自动指向旧版本
  - 不发生路径悬空

### IT-05 生成失败不影响已批准资产拍摄

- 目标：验证资产生成链路故障不会阻断当前拍摄。
- 前置条件：已有批准版本；同时再发起一个新草稿生成任务。
- 步骤：
  1. 让新生成任务失败。
  2. 使用旧批准版本执行自动拍摄。
- 预期：
  - 草稿任务失败被记录
  - 旧版本照常拍摄
  - 剧情主流程不受影响

### IT-06 Strata/Ollama 后端切换

- 目标：验证对白后端可切换。
- 前置条件：Strata、Ollama 均可达。
- 步骤：
  1. 使用 Strata 生成对白。
  2. 切换到 Ollama。
  3. 重新生成同一对白。
- 预期：
  - 两次都返回标准结构
  - 切换不要求修改脚本和人设

### IT-07 LLM 超时与预设台词降级

- 目标：验证对白后端异常不会阻断剧情。
- 前置条件：脚本有预设台词。
- 步骤：
  1. 注入 LLM 超时。
  2. 触发对白事件。
- 预期：
  - 返回 `E3002` 或降级成功结构
  - 当前对白改用预设台词
  - 剧情继续推进

### IT-08 TTS 缓存命中

- 目标：验证相同台词复用语音缓存。
- 前置条件：开启缓存。
- 步骤：
  1. 首次生成某句台词音频。
  2. 再次生成同一句台词。
- 预期：
  - 第二次 `cache_hit=true`
  - 命中次数递增

### IT-09 Lip Sync 失败不阻断剧情

- 目标：验证口型失败时语音和镜头照常执行。
- 前置条件：对白音频已生成。
- 步骤：
  1. 注入 Rhubarb 失败。
  2. 执行对白镜头。
- 预期：
  - 音频仍可播放
  - 角色动作与镜头正常推进
  - 日志记录失败来源

### IT-10 脚本触发器推进

- 目标：验证时间、距离、对话结束、状态四类触发器仍可驱动事件推进。
- 前置条件：脚本覆盖四类触发器且资产版本已锁定。
- 步骤：
  1. 制造满足条件的运行时状态。
  2. 调用事件推进。
- 预期：
  - 每类触发器都正确生效
  - 不满足条件时不会误推进

### IT-11 动作优先级打断

- 目标：验证高优先级动作能打断低优先级动作。
- 前置条件：角色资产已经过统一骨架处理并兼容动作库。
- 步骤：
  1. 触发 idle
  2. 触发 talk
  3. 触发 battle
- 预期：
  - talk 打断 idle
  - battle 打断 talk
  - 状态机与动作日志一致

### IT-12 自动拍摄导出 PNG/EXR

- 目标：验证脚本自动拍摄可导出序列帧。
- 前置条件：镜头序列完整、资产版本锁定。
- 步骤：
  1. 导出 PNG 序列帧
  2. 导出 EXR 序列帧
- 预期：
  - 帧号连续
  - 导出日志具备任务追踪 ID

### IT-13 导播模式录制

- 目标：验证导播模式下可手动切机录制。
- 前置条件：机位包包含多个可切机位。
- 步骤：
  1. 启动导播模式
  2. 切换多个机位
  3. 结束录制
- 预期：
  - 录制文件生成成功
  - 操作记录和视频切机顺序一致

### IT-14 工程保存与重载一致性

- 目标：验证工程、资产锁定关系和后端配置持久化完整。
- 前置条件：工程已配置草稿、批准版本、脚本、机位、后端和音频设置。
- 步骤：
  1. 保存工程
  2. 关闭并重新打开
  3. 比较关键配置
- 预期：
  - 关键配置一致
  - 锁定资产版本不丢失
  - 草稿与批准目录边界清晰

### IT-15 日志与错误码落盘

- 目标：验证生成期和拍摄期都能输出标准日志。
- 前置条件：开启调试日志。
- 步骤：
  1. 触发一次成功资产生成
  2. 触发一次质量门禁失败
  3. 触发一次对白降级
- 预期：
  - 日志可区分生成链路和运行链路
  - 错误码与接口规约一致
  - 每条日志可关联 `trace_id`

## 7. 缺陷分级建议

| 级别 | 标准 |
| --- | --- |
| S1 | 已批准资产无法拍摄、版本锁定失效、工程损坏、导出失败且无恢复路径 |
| S2 | 质量门禁失效、生成失败污染运行期、对白或动作链路错误 |
| S3 | 日志缺失、缓存异常、调试面板信息不完整 |

## 8. 自动化建议

- Schema 校验、质量报告校验、工程读写一致性适合自动化。
- 生成作业状态流转、版本锁定、错误码校验适合接口级自动化。
- 导播模式、镜头观感和资产美术验收更适合半自动或人工验收。
