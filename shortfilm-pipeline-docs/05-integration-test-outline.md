# 集成测试大纲与核心用例

## 1. 目标

验证各模块在“严格对齐 PRD、单模块故障不中断剧情”的前提下能够稳定协同工作，重点覆盖：

- 后端切换
- 熔断与降级
- 音频缓存
- 脚本事件推进
- 动作优先级
- 离线运行
- 导出链路
- 工程读写

## 2. 范围

### 2.1 包含

- 工程管理
- 脚本事件引擎
- 角色状态与动作调度
- Strata/Ollama 双后端适配
- Piper TTS
- Rhubarb Lip Sync
- 音频资源播放
- 自动拍摄与导播录制
- 导出与日志

### 2.2 不包含

- 3D 资产美术质量验收
- 第三方工具内部算法正确性
- 高并发压测到极限吞吐

## 3. 测试环境分层

| 环境 | 用途 |
| --- | --- |
| `env-local-min` | 最小离线验证，使用小模型或保底模式 |
| `env-local-full` | 完整联调，包含 LLM/TTS/Lip Sync |
| `env-export` | 专门验证序列帧与视频导出 |

## 4. 入口与退出标准

### 4.1 入口标准

- 工程文件通过 Schema 校验
- 至少有一套可运行的人设、脚本、机位、动作与音频样例
- Strata/Ollama 至少一套后端可用，或已显式启用保底模式

### 4.2 退出标准

- 核心用例全部通过
- 所有阻断级缺陷关闭
- 对降级路径有明确日志可追踪

## 6. 核心用例

### IT-01 后端切换

- 目标：验证统一网关可在工程配置下切换 Strata 与 Ollama。
- 前置条件：Strata、Ollama 均可达；同一脚本、人设、模型参数已配置。
- 步骤：
  1. 使用 Strata 运行对白生成。
  2. 保存工程。
  3. 切换活动后端为 Ollama。
  4. 重新运行同一对白生成。
- 预期：
  - 两次请求均成功返回标准结构。
  - 调试面板显示后端字段变化。
  - 不需要修改脚本、人设与事件定义。

### IT-02 后端超时与预设台词降级

- 目标：验证 LLM 超时不会中断剧情。
- 前置条件：脚本事件包含预设台词；LLM 超时阈值设为较低值便于触发。
- 步骤：
  1. 注入后端超时。
  2. 触发对白事件。
- 预期：
  - 返回 `E3002` 或降级成功标志。
  - 剧情继续推进。
  - 当前对白使用预设台词。
  - 日志中 `degraded=true`。

### IT-03 熔断打开与恢复

- 目标：验证连续失败后熔断打开，恢复后可重新闭合。
- 前置条件：已启用熔断规则。
- 步骤：
  1. 连续触发后端超时或不可达，达到熔断阈值。
  2. 再次发送对白请求。
  3. 等待熔断冷却窗口。
  4. 恢复后端并发送探测请求。
- 预期：
  - 熔断打开后立即返回 `E3005`。
  - 剧情侧直接使用预设台词。
  - 探测成功后熔断恢复为 `closed`。

### IT-04 TTS 缓存命中

- 目标：验证相同台词不重复生成音频。
- 前置条件：开启缓存；同一 voice 配置不变。
- 步骤：
  1. 首次生成指定对白音频。
  2. 再次对相同文本发起 TTS。
- 预期：
  - 第二次返回 `cache_hit=true`。
  - 不重复调用耗时 TTS 过程。
  - 缓存命中次数递增。

### IT-05 Lip Sync 失败不阻断剧情

- 目标：验证 Rhubarb 失败时角色仍可说话并继续镜头。
- 前置条件：对白音频生成成功。
- 步骤：
  1. 注入 Rhubarb 执行失败。
  2. 触发对白镜头。
- 预期：
  - 音频仍可播放。
  - 口型驱动缺失，但角色状态与镜头继续推进。
  - 日志记录失败来源为 `lipsync_service`。

### IT-06 脚本触发器推进

- 目标：验证时间、距离、对话结束、状态四类触发器可驱动事件推进。
- 前置条件：样例脚本覆盖四类触发器。
- 步骤：
  1. 依次制造满足条件的运行时状态。
  2. 调用事件推进。
- 预期：
  - 每类触发器都能触发正确事件。
  - 未满足条件时不会误推进。

### IT-07 动作优先级打断

- 目标：验证高优先级动作可打断低优先级动作。
- 前置条件：角色同时配置 idle、talk、battle 三类动作。
- 步骤：
  1. 先触发低优先级 idle。
  2. 再触发中优先级 talk。
  3. 最后触发高优先级 battle。
- 预期：
  - talk 打断 idle。
  - battle 打断 talk。
  - 状态机与动作日志一致。

### IT-08 离线保底模式

- 目标：验证断网与关闭大模型时仍可成片。
- 前置条件：脚本包含预设台词与动作。
- 步骤：
  1. 停止 LLM 后端。
  2. 启用保底模式。
  3. 执行自动拍摄。
- 预期：
  - 不访问 LLM。
  - 仅使用预设台词、动作与本地音频链路。
  - 剧情完整输出。

### IT-09 自动拍摄导出 PNG/EXR

- 目标：验证脚本自动拍摄可导出序列帧。
- 前置条件：存在完整镜头序列。
- 步骤：
  1. 以 PNG 序列帧导出一次。
  2. 以 EXR 序列帧导出一次。
- 预期：
  - 输出目录中帧号连续。
  - 导出日志具备任务级追踪 ID。

### IT-10 导播模式录制

- 目标：验证导播模式下可人工切机并录制。
- 前置条件：机位包包含多个可切机位。
- 步骤：
  1. 启动导播模式。
  2. 手动切换多个机位。
  3. 结束录制并导出。
- 预期：
  - 录制文件生成成功。
  - 切机顺序与导播操作记录一致。

### IT-11 工程保存与重载一致性

- 目标：验证工程持久化完整性。
- 前置条件：工程中已配置资产、人设、脚本、机位、后端与音频设置。
- 步骤：
  1. 保存工程。
  2. 关闭并重新打开工程。
  3. 比较关键配置项。
- 预期：
  - 关键配置一致。
  - 引用路径不丢失。
  - 缓存索引与主工程配置边界清晰。

### IT-12 日志与错误码落盘

- 目标：验证日志分级与标准错误码输出。
- 前置条件：开启调试日志。
- 步骤：
  1. 触发一次成功对白。
  2. 触发一次后端失败并降级。
  3. 触发一次导出任务。
- 预期：
  - `debug`、`business`、`error` 日志可区分。
  - 错误码与接口规约一致。
  - 每条日志可关联 `trace_id` 和 `request_id`。

## 7. 缺陷分级建议

| 级别 | 标准 |
| --- | --- |
| S1 | 剧情无法继续、工程损坏、导出失败且无恢复路径 |
| S2 | 降级失效、后端切换失效、动作或镜头链路错误 |
| S3 | 日志缺失、缓存命中异常、调试信息不完整 |

## 8. 自动化建议

- Schema 校验、工程读写一致性、错误码校验适合自动化。
- 后端切换、缓存命中、熔断状态转换适合接口级自动化。
- 导播录制与镜头观感更适合半自动或人工验收。
